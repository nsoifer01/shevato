# Quote Scout engineering findings

## The dataset that made the product real

- **A credential is not the only way to get a real price.** The first build of this app shipped with every pricing vertical dark because each candidate API needed a key or a contract, and it stopped there. The CMS Exchange Public Use Files carry the actual premiums insurers filed for the plan year, need no key, no registration and no agreement, and are updated for every plan year. Look for the bulk publication before concluding a vertical is blocked; regulated markets usually have one.
- **The PUFs alone are not enough, and the missing pieces are the hard part.** The Rate PUF prices a plan by *rating area*, and nothing in the PUF set says which rating area a county is in. That mapping only exists as one HTML page per state on CCIIO, and ZIP-to-county only exists in the Census ZCTA relationship file. Two-thirds of the build script is joining those three shapes together.
- **The CCIIO county tables contain real typos**: `Kosclusko`, `Dubols`, `Chautaugua`, `Vermillion`, `Trail`, `Deleware`. An exact-name join silently drops those counties, and a dropped county means a shopper there sees no plans at all. Fold confusable glyphs (l/i/1, q/g, 0/o, rn/m), collapse doubled letters, then allow one edit, requiring a unique match at every step, and **fail the build** on anything still unresolved. A warning would have shipped 14 counties of silence.
- **`Age` in the Rate PUF is not a number.** The lowest and highest buckets are `0-14` and `64 and over`. Parsing with `Number()` leaves age 64 empty, and if the builder requires a complete age vector, *every plan in the country* is dropped. That produced a clean run emitting zero plans, which is a far better failure than emitting most of them.
- **Verify the decode against the source, not against itself.** 1,440 spot checks across all 30 states, six ages and both tobacco settings, comparing the shipped shards to the raw Rate PUF CSV, is what makes it defensible to call these numbers real. A round-trip test of your own encoder proves nothing about the join.
- Sanity anchors that catch a wrong plan year immediately: catastrophic plans carry a deductible equal to the annual cost-sharing cap ($10,600 for 2026), and standardised expanded bronze is $7,500 / $10,000.
- **Delta-encode in base 36.** Premiums rise smoothly with age, so 47 explicit values per plan and rating area is 13.7 MB while a base value plus 46 deltas is 8 MB, 3.5 MB gzipped. Nothing is rounded; it decodes to the filed cent. The ACA federal age curve does *not* reproduce filed rates, so storing a base rate and a curve is not an option: 22,127 of 24,217 plan-and-area combinations have a distinct age-ratio vector.
- **Coverage is a product statement, not a footnote.** The Exchange PUFs only carry HealthCare.gov states, so a Californian gets nothing. Ship the nationwide ZIP-to-state map alongside the covered data purely so the app can tell that person their state runs its own exchange, rather than showing them the same message as a mistyped ZIP.
- **Eligibility rules belong in the adapter.** Catastrophic plans are the cheapest medical plans in the file, so they head the results by default, and almost nobody who sees them can buy one: they are restricted to under-30s or a hardship exemption. Filtering them for 30-and-over changed the leading result for a 40-year-old in Austin from a $257 plan they cannot buy to a $387 plan they can. Say the plans were excluded and why, rather than filtering silently.
- **A published rate needs its own status.** `ESTIMATE` understates it (nothing was modelled) and `VERIFIED QUOTE` overstates it (no one quoted this person). `AUTHORITATIVE PUBLIC RATE` is the honest third thing, and the UI must describe a static dataset by its vintage: "Plan year 2026 rate, published by CMS on 15 October 2025", never "retrieved 4 seconds ago".
- **Commit the derived data, do not rebuild it at deploy.** 300 MB of CSV per deploy would be slow, and it would make every deploy and every comparison depend on CMS being up. 3.8 MB of committed gzipped shards plus `included_files` is faster, deterministic, and cannot fail at the worst moment. Shards are gunzipped lazily with an LRU of four states so a warm instance never holds all thirty.

## Product and platform

- Metering should follow spend, not requests. The original handler refused every POST when Netlify Blobs was down, which was right while every provider was an outbound paid call. A comparison served from the bundled dataset spends nothing, so it stays up during a Blobs outage; it is still counted when the store can record it, and still bounded by the platform rate limit. Only a request that can reach a paid API fails closed.
- "Unavailable" must mean we tried and could not. Reporting a never-configured provider as unavailable on every single search taught users to ignore the line and made the CA refusal read like an outage. Providers carry `enabled` through to the client, and both the summary count and the per-provider notice skip the ones that were never in the running.
- Two adapters describing the same products will duplicate every result. The keyed CMS API and the bundled dataset both cover marketplace plans, so the keyed one supersedes the bundled one, decided at request time on what is actually usable, so a Blobs outage falls back to the dataset instead of emptying the vertical.
- Lead with the group that holds the best option under the current ranking mode. Ordering product groups by key put the first alphabetical group on screen, which is rarely the answer anyone came for.
- Provider availability is the product boundary: no keys/contracts are established by code. Keep unavailable verticals outside the active input selector. Vehicle decoding is useful public data, not a substitute for real quotes.
- EasyPost developer terms do not automatically permit a white-label comparison platform. The agreement flag and explicit carrier IDs are required in addition to a key. Rate-only `/beta/rates` avoids creating shipments; keep it labeled Beta and never expose a test-mode amount.
- An API account’s shipping rate is not purchasable on an arbitrary carrier website. No handoff is better than falsely suggesting the same rate can be bought there.
- CMS ZIPs can cross counties and state lines. Never pick the first county silently. The additional-question answer must be validated against the lookup result again.
- CMS uses `In-Network` and individual cost types. Multiple medical/drug or CSR rows cannot be collapsed to the minimum. Unknown costs sort last, not as zero. Annual premium is not expected annual cost.
- The no-subscription/no-lead UX does not remove insurance producer obligations. Auto/home stay disabled until an actual licensed-partner contract and legal review exist; no homemade state minimum limits.
- Private cache isolation includes per-tab capability, input, provider and config fingerprint. Config changes must not serve prices under the old account. Circuit and pending maps must outlive one request to be meaningful; engine instances are reused per config.
- Shared main.css overrides button colors and strong text. App-scoped pins and computed-style/axe checks are required, including the simple commitment copy.
- Existing app-order tests had three literal eight-app counts despite the manifest convention. They now derive counts from the manifest so adding Quote Scout preserves the invariant rather than merely changing a magic number.
- Static-only serving cannot run Netlify Functions. Its unavailable state is intentional; meaningful E2E flows intercept the function endpoint with fixtures isolated in the E2E suite. Do not change the app to fake results for localhost.
- Preview artwork is a screenshot of the empty vehicle form; fixture price images are not marketed as real offers.

- Use Netlify runtime `context.deploy.context` to distinguish production and previews; build-time `CONTEXT` is not a reliable runtime source. A regression test prevents a stale environment value from enabling paid calls in a preview.
- Duplicate detection must include the actual carrier/issuer and health plan identity. Different carriers can return the same service label and amount.

- Root publishing includes source directories, so forced 404 routes protect Quote Scout fixture paths. This is independent of the normal application import boundary and does not change other apps’ runtime assets.
